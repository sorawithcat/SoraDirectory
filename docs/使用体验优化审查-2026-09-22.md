# 当前使用体验优化审查

日期：2026-09-22。源码基线：`5d67583`。

本轮只阅读源码及已有优化记录，没有修改产品代码，没有运行测试、构建、检测器或浏览器验收。下述实现事实已从代码核对；竞态、性能和设备表现仍需在用户授权测试后复现，不能视为已经发生的数据损失或实测卡顿。

## 结论与取舍

当前已具备目录位置恢复、命令搜索、工作区模式、草稿快照、媒体管理、导出预检和拆分媒体授权。下一轮应优先完善这些功能之间的数据边界和操作衔接。

整体重做编辑器会扩大风险；推荐沿用现有架构，先补保存事务、草稿与媒体引用保护，再整理操作入口。P1 表示存在内容完整性风险的路径，P2 表示效率与可理解性改进，不代表均已运行复现。

## U1：媒体清理与草稿保护

**现状与根因：**“新建”经过确认后调用 `MediaStorage.clearAll()`，清除共享媒体数据库及 OPFS 媒体目录。草稿和快照保存的是目录正文及媒体 ID 引用，没有独立媒体副本。媒体库又用当前 `mulufile` 的引用情况判断共享资源是否孤立，未将其他文档和历史快照计入。

**影响：**新建文档，或在文档 B 中删除被标为孤立的资源后，文档 A 的历史草稿可能只能恢复正文，无法恢复原媒体。现有确认框已说明清空全部媒体，但不能解决快照引用失效。

**推荐最小修复：**新建只重置当前工作区；将清理放入明确的存储管理动作。清理前纳入保留草稿、快照和文档的引用集合，展示实际释放空间。长期可维护文档与资源的引用索引，避免逐份复制大视频。

**源码：**`js/toolbar.js:314`；`js/videoStorage.js:1031`；`js/workspaceFeatures.js:294`、`:858`、`:908`、`:1168`。

**后续验收场景（未执行）：**A 中插入媒体并创建快照，切换或新建 B，再恢复 A；共享媒体不应因 B 的清理而失效。

## U2：保存完成不应掩盖未写入的内容

**现状与根因：**

- `.sora` 先固定目录数据，再异步读取和写入媒体；结束后直接执行 `clearUnsavedChanges()`，重设当前数据的基线并清除草稿。没有用文档 ID 与编辑版本区分保存期间新增的编辑。
- 打开 `.sora` 后媒体继续后台导入，普通 `.sora` 保存路径未等待这项任务；打包函数遇到缺失媒体只记录日志并跳过。网页导出已有等待逻辑，但媒体导入任务会捕获错误，等待结束也不等于导入完整成功。
- 下载回退在点击“保存到设备”后即返回成功，随后清除未保存状态和草稿；这条路径只确认发起了下载。

**影响：**在大包导入、长时间保存或下载取消等场景下，界面上的“已保存”可能比实际文件状态更乐观。

**推荐最小修复：**建立统一保存入口，固定文档 ID、内容快照和编辑版本，合并重复保存请求；导入任务返回可判断的结果，缺失媒体明确提示补齐或导出不完整副本。完成后仅在版本一致时清除未保存标记，版本变化则保留草稿。下载回退显示“已发起下载”并保留恢复副本。

**源码：**`js/fileOperations.js:120`、`:278`、`:378`、`:473`、`:714`、`:958`、`:1960`、`:3436`。

**后续验收场景（未执行）：**保存期间继续编辑；媒体尚未导入时保存；导入失败后导出；下载发起后取消。分别检查文件、未保存标记与草稿是否一致。

## U3：草稿恢复要覆盖重新打开文件

**现状与根因：**启动时只读取当前文档身份对应的最新草稿。加载文件后先采用该文件的身份，再调用 `resetAfterLoad()`；该方法直接对应删除最新草稿的 `clear()`。恢复提示只有“恢复草稿”和“忽略并删除”，关闭/取消也进入删除分支。草稿管理器只列当前文档的历史快照，缺少跨文档的最新草稿入口。

**影响：**A 留有未保存草稿，切到 B 后再打开 A，A 的最新草稿可能在比较前被清除；用户暂时不恢复，也会失去这份最新恢复点。历史快照仍可能存在，但不保证包含最后编辑。

**推荐最小修复：**打开文件时先读取同文档草稿并比较，再提供恢复或继续使用文件；取消、关闭保留草稿，删除作为独立动作。草稿管理增加按文档查看最新草稿，并在文档切换前完成当前草稿写入。

**源码：**`js/main.js:85`；`js/fileOperations.js:1067`、`:1085`；`js/workspaceFeatures.js:232`、`:475`、`:563`、`:584`。

**后续验收场景（未执行）：**A/B 来回打开；A 的草稿比文件新；关闭恢复弹窗；无历史快照时恢复最新草稿。

## U4：日常保存与导出设置分开

**现状与根因：**Ctrl+S 调用 `handleSave()`，有部分目录变化时先选择保存范围，每次再选择是否加密；即使已有可写 `.sora` 句柄，也在选择后才执行写入。“另存为”按格式、范围、预检、加密、密码和文件位置逐个弹窗，发布设置另有入口。

**影响：**高频保存被低频选项打断，导出时难以回看完整选择，容易在后续步骤发现前面选错。

**推荐最小修复：**普通保存沿用当前文档格式与安全属性；首次保存或无法沿用时选择目标。增量、差异、范围、加密进入导出面板，集中展示文件数量、大小估计、媒体策略与兼容性说明。保留高级能力，并记住非敏感选项；密码不持久化。

**源码：**`js/main.js:18`；`js/fileOperations.js:1916`、`:3072`、`:3422`；`js/toolbar.js:373`。

## U5：帮助与作品内容分离

**现状与根因：**“使用说明”调用 `loadHelpManual()`，将帮助目录插到当前文档最前面，重建目录树、展开全部并切换到首目录；已有内容时标记未保存。确认提示仅在原文档已有未保存修改时出现。

**影响：**用户只是查用法，也会改变作品、当前位置及后续导出的内容。

**推荐最小修复：**复用现有动态帮助内容，在独立帮助面板展示；保留搜索和内部跳转。将“插入使用示例”单独作为明确操作，关闭帮助回到原目录和选区。

**源码：**`js/toolbar.js:1243`、`:1274`、`:1282`、`:1293`；`js/main.js:76`。

## U6：手机操作入口与状态同步

**现状与根因：**900px 以下隐藏原工具栏，显示快捷按钮代理。代理只在创建时复制文字、标题和点击行为，未同步原按钮的 `disabled`、保存星号和状态；后续编辑只更新原保存按钮。“更多”从工具栏按钮收集功能，未合入命令面板已有的 `SoraFeatureCommands`，也没有搜索。

**影响：**手机快捷保存按钮可能缺少当前未保存提示；自定义为撤销等动作后，代理可能看起来可点却没有效果。扩展功能仍可经过全局搜索进入，但在“更多”中不直接可见。

**推荐最小修复：**快捷栏、更多菜单和 Ctrl+K 共用命令描述及状态更新；更多菜单加入搜索、分组与最近使用，保留当前四个自定义快捷位。

**源码：**`js/workspaceFeatures.js:68`、`:1293`、`:1310`、`:1355`、`:1683`；`js/fileOperations.js:293`。

## U7：问题定位避免目录名称误匹配

**现状与根因：**问题保存为字符串，`matchDirectory()` 使用 `text.includes(row[2]) || text.includes(row[1])` 找第一个匹配目录。徽标归属、目录筛选和点击跳转都复用这个判断。

**影响：**目录名相同，或存在“介绍”“产品介绍”等包含关系时，问题可能归到错误目录；定位也只到目录，没有具体锚点或正文片段。

**推荐最小修复：**问题内部使用 `{ type, directoryId, targetId, message }`，文案只用于显示；按稳定 ID 定位，并对可以确定的位置短暂高亮。旧报告文字可继续兼容。

**源码：**`js/workspaceFeatures.js:1421`、`:1426`、`:1530`；`js/fileOperations.js:2888`。

## U8：大项目后台检查按变化范围工作

**现状与根因：**问题中心监听整个文档的 `input/change` 后调度完整预检。预检虽调用 Worker 清单统计，仍在主线程逐目录创建模板、解析 HTML、检查标题/链接/方法。草稿写入也复制全文、计算完整指纹，并读取全部快照后筛选当前文档。

**影响：**大项目编辑时存在重复遍历和主线程负担；具体耗时与输入流畅度尚未测量，不能据此宣称已经卡顿。

**推荐最小修复：**从正文和结构变更事件携带受影响目录 ID，缓存目录级分析结果，合并失效范围；全量检查保留在导出前。草稿按文档索引读取，快照整理降低频率。先减少重复工作，再按真实测量决定是否迁移更多计算。

**源码：**`js/workspaceFeatures.js:246`、`:263`、`:287`、`:1457`、`:1557`；`js/fileOperations.js:2835`、`:2877`；`js/performanceBudget.js:12`、`:58`。

2. 接着处理 U4–U7：高频操作、帮助、手机入口和问题定位。
3. U8 先收敛重复计算，真实性能指标留待授权后测量。

加密拆分视频目前仍逐块解密后组装完整 Blob（`js/fileOperations.js:7876`），大视频内存上限值得保留为专项。已有体积风险预检、手动加载和本地授权，不应将其列为缺失功能。流式播放涉及媒体格式及兼容性，建议在有代表性大文件和明确设备范围后单独设计。
