# 格式功能审查与扩展建议

审查基线：`224f668`，2026-09-22。范围为正文格式、相关编辑操作、内置说明、保存与导出转换。仅阅读源码和参考资料；没有运行测试、语法检查、构建、浏览器操作或性能测试，没有修改产品代码。下文的操作例子是待验收场景，不是已执行的复现记录。

## 结论

现有基础格式已比较齐全，优先工作是让格式转换保留内容、选区准确、编辑可撤销，再补充日常排版和少量新格式。继续单独增加工具栏按钮，会放大当前格式处理的共性问题。

建议先处理 F1–F7，再补齐清除格式、段落排版、表格操作，随后加入提示块、直接插入的折叠块和脚注。新增格式必须同时定义编辑、保存、网页导出及 Markdown 降级行为。

## 现有功能建议修改

### F1 / P1：格式命令必须限制在当前正文选区

- 证据：[applyFormat](/E:/Github/SoraDirectory/js/formatToolbar.js:834) 优先使用缓存 Range，否则直接使用页面全局 Selection，执行前没有确认两端都属于当前编辑区；[快捷键](/E:/Github/SoraDirectory/js/toolbar.js:1400) 在 document 上处理 Ctrl/Cmd+B/I/U，没有排除帮助弹窗、其他输入框或输入法组合状态。
- 影响：在说明弹窗选中文字后触发快捷键，存在改到说明 DOM 的路径；缓存选区也没有绑定目录和内容版本，可能操作旧选区。
- 建议：统一取得正文选区，检查节点仍连接、起止点属于当前编辑区且目录未变化；弹窗确认回来后再次检查。正文以外不执行正文格式命令。

### F2 / P1：取消格式会选错重复文字，并丢失嵌套格式

- 证据：[部分取消格式](/E:/Github/SoraDirectory/js/formatToolbar.js:1534) 用 `fullText.indexOf(selectedTextClean)` 定位，然后把前、中、后三部分重建成纯文字。判断是否取消还会取选区内第一个相交的格式标签。
- 影响：在同一加粗段落内选择第二处相同文字，可能取消第一处；原来嵌套的链接、斜体、颜色及节点属性可能丢失。混合选区的加粗状态也没有明确规则。
- 建议：按真实 Range 边界拆分节点，仅移除指定格式，保留其他节点和属性；混合选区首次点击统一应用，全选已应用时才统一取消。

### F3 / P1：列表转换丢失格式，并把普通文字重新当 HTML 解析

- 证据：[三种列表转换](/E:/Github/SoraDirectory/js/formatToolbar.js:1409) 使用 `selectedText.split('\n')`，把未转义文字拼接为 `<li>`；[插入路径](/E:/Github/SoraDirectory/js/formatToolbar.js:1584) 先赋给 `innerHTML`，再插入页面。
- 影响：链接、粗体等会被压成纯文字；文字中的 `<b>` 等内容可能被当作标签；DOM 文本边界也不保证等同于视觉段落。之后存储时的净化不能代替插入前处理。
- 建议：按选中的段落/列表项搬移 DOM 子节点，保留链接、媒体及行内格式；纯文字通过 textContent 创建。支持列表类型互换、取消列表、缩进/减少缩进、空项回车退出，避免重复套列表。

### F4 / P1：标题、正文和引用需要按块转换

- 证据：[标题分支](/E:/Github/SoraDirectory/js/formatToolbar.js:1040) 和[段落/引用分支](/E:/Github/SoraDirectory/js/formatToolbar.js:1444) 直接包裹选中 HTML，通用插入路径没有提升到合法块级位置。
- 影响：光标在段落内无法直接改标题；跨段落选择或 H1 改 H2 可能构造嵌套块，存储重新解析后结构可能变化。这是源码可见风险，具体浏览器表现尚未验收。
- 建议：用“正文 / 标题 1–6”类型选择器改变当前块类型；跨段落逐块转换；引用作为独立容器处理，保留显式锚点和内部链接。不要以字号代替标题语义。
- 参考：HTML 段落只接受短语内容，遇到部分块元素会自动结束。[MDN：p 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/p)

### F5 / P1：表格取消失效，缺少尺寸校验和后续编辑

- 证据：[表格分支](/E:/Github/SoraDirectory/js/formatToolbar.js:1461) 连续询问行列，两次都没有处理 null；`parseInt(value) || 3` 把取消、0 或非法值当成默认 3，也没有上限。审查范围内未找到增加/删除行列、合并拆分单元格或表格属性入口。
- 影响：取消仍可能插入表格；负数可能生成不完整结构，极大值会同步生成大量节点；插入以后难以调整结构。
- 建议：一张表单填写行列和表头，取消立即结束；限制正整数与总单元格数。先补增删行列、表头、单元格对齐和整表删除；合并/拆分作为后续扩展，不混进第一步安全修复。

### F6 / P1：连续编辑格式文字时会被强行移出

- 证据：[粗体等命令](/E:/Github/SoraDirectory/js/formatToolbar.js:1101) 无文字选区时直接返回；[input 监听](/E:/Github/SoraDirectory/js/preview.js:901) 检测到光标位于 STRONG/EM 等标签中，就创建标签外文本节点并移动光标；该逻辑没有输入法组合状态判断。
- 影响：不能先开启粗体再连续输入；在已加粗句子中补字也会触发移出逻辑。中文输入法组合过程受到干扰的程度需要真实输入验收。
- 建议：区分“输入点启用格式”和“给选区加格式”；在原格式内部编辑时保持光标，只有明确退出格式才移出。组合输入结束前不重写当前节点或选区。

### F7 / P1：正文格式操作缺少统一撤销记录

- 证据：[格式命令](/E:/Github/SoraDirectory/js/formatToolbar.js:1584) 直接修改 DOM，没有接入产品撤销记录；[DirectoryHistory 快捷键](/E:/Github/SoraDirectory/js/workspaceFeatures.js:802) 明确跳过正文编辑区。本轮没有发现正文专用的 historyUndo/historyRedo 或统一格式事务入口。
- 影响：不能把“改成 Selection/Range”直接视为已有完整的正文撤销；浏览器原生输入历史与脚本格式修改可能不一致。当前实际 Ctrl+Z 行为未运行验证。
- 建议：建立正文编辑事务与历史记录，覆盖格式、列表、表格、代码块和颜色修改，并保存选区；与目录历史明确分工。不要只给每个按钮单独堆补丁，也不建议重新回退到已弃用 execCommand。
- 参考：直接 DOM 修改与保留原生 undo buffer 的编辑命令并不等价。[MDN：execCommand 的撤销说明](https://developer.mozilla.org/en-US/docs/Web/API/Document/execCommand)

### F8 / P2：文字色可能把背景色误认成当前颜色

- 证据：[样式查找](/E:/Github/SoraDirectory/js/formatToolbar.js:992) 使用字符串 includes；[取值](/E:/Github/SoraDirectory/js/formatToolbar.js:1028) 使用未限定属性边界的正则。查询 `color` 也会匹配 `background-color`。
- 影响：已有背景色时打开文字色面板，默认色可能来自背景。完整选中判断还依赖文字相等，应与 F2 一起改为 Range 判断。
- 建议：使用 `element.style.getPropertyValue('color')` 等精确属性读取，支持混合色状态和恢复默认色。保留现有最近颜色及对比度提示。

### F9 / P2：代码块“纯文本”与高亮实现不一致

- 证据：[语言选项](/E:/Github/SoraDirectory/js/formatToolbar.js:3) 提供“纯文本（无高亮）”，但 [highlightCode](/E:/Github/SoraDirectory/js/formatToolbar.js:1804) 对空语言也执行字符串、注释和数字规则；只有部分语言有专门规则。
- 影响：纯文本仍产生高亮；仅有语言标签不等于完整支持该语言语法。注释先于字符串匹配等规则也需要后续覆盖实际代码样本。
- 建议：纯文本直接转义返回；语言标签与高亮支持范围分开；原始代码作为保存/编辑来源，高亮只作为显示结果。先修现有实现，不为扩充语言名单立即引入大依赖。

### F10 / P1：Markdown 往返会丢失已有格式

- 证据：[nodeToMarkdown](/E:/Github/SoraDirectory/js/knowledgeBaseInterop.js:184) 没有任务复选框状态转换；代码块不输出语言；颜色、高亮、上下标等走子内容回退；表格输出 outerHTML。[markdownToHtml](/E:/Github/SoraDirectory/js/knowledgeBaseInterop.js:146) 不处理任务状态、Markdown 表格及 HTML 块，行内处理会转义原始 HTML。导出警告目前提示方法逻辑降级，没有逐项说明这些格式损失。
- 影响：任务列表变普通列表、代码语言消失；本工具导出的 HTML 表格再导入时可能变成标签文字。
- 建议：先补任务列表、代码语言及表格的往返；为不能无损转换的样式给出明确警告和选择。`.sora`、网页、Markdown 分别标明保真边界，不承诺 Markdown 支持所有网页交互。

### F11 / P2：工具栏缺少格式状态，新增格式不宜继续平铺

- 证据：[顶部栏](/E:/Github/SoraDirectory/index.html:2456) 与[悬浮栏](/E:/Github/SoraDirectory/index.html:2575) 分别手写命令；顶部有 H4–H6、表格、段落、分隔线，悬浮栏没有这些入口。格式命令没有统一的选区状态计算或 aria-pressed 更新。
- 影响：用户看不出当前位置正在使用什么格式，也无法区分“全部已应用”和“部分已应用”；继续添加按钮会增加查找成本。具体移动端尺寸和遮挡没有实测。
- 建议：共用格式定义，按文字、段落、插入分组；标题合并为类型选择；悬浮栏保留常用文字格式和更多入口。沿用现有命令搜索，不再建立第三份命令表。

## 值得补充的操作与格式

以下是本项目的扩展建议，不代表这些格式是近期出现的新标准。推荐顺序结合现有目录编辑、说明文档和离线网页用途。

| 编号 | 建议 | 优先级 | 使用价值与实现边界 |
| --- | --- | --- | --- |
| N1 | 清除格式、恢复正文 | 高 | 区分“清除文字样式”和“转换为正文”；前者保留链接、锚点、方法、媒体与列表结构，避免一键清空语义。属于编辑操作。 |
| N2 | 段落对齐、行距、段前段后间距 | 高 | 提供少量预设，作用于当前块/选中块；保留默认左对齐，不改变整个导出页面。列表缩进使用列表结构操作。字号可后续提供受控档位，避免用任意字号模拟标题。 |
| N3 | 提示块 | 高 | 提示、注意、警告、成功等内容块；标题和正文可编辑。类型用文字配合颜色表达；共享编辑/导出样式，Markdown 映射为引用或明确的扩展语法。 |
| N4 | 直接插入的折叠块 | 高 | 插入后即可编辑标题和内容、设置初始展开状态，适合补充说明。复用 HTML details/summary，补编辑态选区与导出约定；保留现有“方法触发折叠组件”用于动态场景。 |
| N5 | 脚注/尾注 | 中 | 正文编号、注释区、双向返回；复用稳定 ID 和内部链接能力，处理复制目录、删除引用和重新编号。先做当前目录内脚注，不扩为全项目引用管理。 |
| N6 | 键盘按键、术语解释 | 中 | 用按键样式展示 Ctrl+S 等操作；用术语/说明成对结构编写名词表和参数解释。使用普通语义 HTML，并在 Markdown 中明确回退形式。 |
| N7 | 格式刷 | 后续 | 复制允许的文字/段落样式，不复制链接目标、锚点 ID、方法配置或组件状态。依赖 F1、F2、F7 完成后再加入。属于编辑操作。 |

`details` 原生提供折叠/展开语义，适合作为 N4 的基础；编辑器内如何保护摘要和正文结构仍需自行实现。[MDN：details 元素](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/details)

可选扩展：数学公式、流程图、拼音/注音、复杂多栏、合并表格单元格。需要明确使用需求及离线导出成本后再定，暂不引入渲染库。任务列表、图注、标签页、步骤条、问答、图库已有实现，优先完善入口与编辑方式。

## 实施建议与验收边界

1. **格式基础处理**：先处理正文选区边界、非破坏性节点转换、输入法和撤销；把格式定义、状态计算和写入事务集中起来，保持当前 HTML 存储及经典脚本结构，不直接更换整套编辑器。
2. **常用编辑能力**：修表格取消与大小限制，补行列操作、清除格式、正文/标题转换、段落排版，并修代码/颜色/Markdown 保真问题。
3. **新增内容格式**：提示块和直接插入的折叠块优先；脚注和语义文字格式次之。新样式要同时覆盖编辑器和导出页，旧内容不做批量重写。

获得测试授权后，验收应包含：重复文字的局部取消格式、保留嵌套链接、文字中带 HTML 符号的列表转换、跨段落转标题、取消表格、格式与输入交替撤销、中文输入法组合、帮助弹窗快捷键、任务/代码/表格 Markdown 往返，以及桌面与手机的实际操作。未完成这些场景前，只能报告源码实施，不能报告体验验收通过。
