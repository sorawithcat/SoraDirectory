# 点击定位输入

独立的正文编辑功能，统一处理各种格式周围的光标落点。用户选择：点击正文下方较远空白时，补出空行，让光标落在点击的行。

## 原因与处理

正文使用 contenteditable。文字中的点击由浏览器定位，但块前后、块间空隙和编辑区剩余空间不一定存在可输入节点。折叠块只是其中一种表现：现有段落包装进块后，块外可能没有普通段落，点击空白会落回块内。

仅在某种格式后补一行不能覆盖旧内容、其他格式及更远的空白区域，因此新增 `js/editorClickInput.js`，根据正文实际布局寻找可输入位置：

- 已有文字保持原生点击定位；已有空白行可以直接落下光标。
- 块前后和块间空隙创建或复用普通段落，适用于折叠块、提示块、表格、列表、引用、代码块和媒体周围的正文。
- 正文或可编辑内容区域末尾的空白，按当前行高补足换行；已有空白段落继续复用。
- 横向空白不自动补空格、不改变对齐；块间插入新段落会正常推动下方内容。
- 新增的空行属于实际正文，可保存；一次点击产生的换行作为一次正文事务撤销或重做。
- 点击仅移动光标时不写入正文；加载文档时不自动添加占位段落。
- 拖选、双击选词、长按、滚动、输入法组合输入、修饰键选区和组件交互不触发补行。代码块继续通过既有弹窗编辑。
- 单纯补行不重建组件，保留当前折叠/展开状态。编辑区底部保留至少一行的可点击空间；空段落保留行高。

同步了内置“编辑与格式”说明。没有新增依赖，没有改变文件格式。
